# Web till architecture panel

Choose **Architecture** in the header or checkout terminal, including after a
failed checkout. Services and flows can be selected in the SVG or through the
equivalent labelled buttons. The native modal supports Escape, keyboard focus
containment and focus return to the exact opener. Small screens scroll the SVG
inside the panel while explanations and buttons stack below it. Optional
direction animation respects reduced motion; it is not live traffic.

## Topology and incident evidence

The customer path is browser -> Azure App Service checkout -> a per-country
primary/legacy HTTP price lookup on a private Azure VM. The VM also hosts the
synthetic BE/NL POS simulators. Cloud and simulated datacenter VNets are peered;
this is not a VPN or a real on-premises deployment.

Monitor/Application Insights, Log Analytics, alert investigation and the optional
Arc repair path are distinguished from customer traffic. AlertsOnly omits
agents; WithArc is needed for the service-repair path. The diagram does not
discover optional component installation. The separate read-only Foundry
assistant and optional GitHub/Copilot code loop are explained as extensions,
not checkout dependencies.

Evidence comes from **this browser's actual checkout attempts**, separately for
BE and NL. A successful response supplies the real `priceRoute` and
`priceLookupMs`; a lookup of at least 1,000 ms is marked slow. HTTP 503 marks
the selected country's price path failed, not a confirmed stopped service or
network fault. Other unusable responses are unknown. One country's result
never establishes the other country's health. Recovery needs a new successful
checkout, not just a working web process.

While open, the panel reads the existing `/health` endpoint every five seconds,
with a bounded timeout. This reports process/configuration only and makes no
backend request. Route changes invalidate previous country evidence once
observed. All samples become unknown after 30 seconds without fresh evidence.
**No checkout or price probe is generated by opening the diagram.** Make a
normal checkout in each country to show fresh results. Failures elsewhere or
after the last checkout are not automatically discovered. Monitor ingestion,
SRE activity, native approval and confirmed root cause are not fetched.

## Publish through existing deployment ownership

No live website changes until the updated checkout frontend is published.
Package `app.py`, `requirements.txt` and the complete `static` directory together,
as the existing `Publish-Frontend` helper in `Invoke-CheckoutDemo.ps1` does.
The changed `app.py` must accompany the new assets because it allowlists their
routes. New environments receive the feature through normal authorized `Up`.

The public lifecycle has no standalone frontend Publish action; do not rerun
`Up` against retained ownership merely to update this UI. For an existing site,
an operator must authorize an owned App Service ZIP publication of that same
frontend package through the established release process, or use a fresh demo
environment. The routes-only `checkout-deploy.yml` does not publish Python or
static website files. No fault injection, infrastructure change or approval
bypass is needed by this feature.

```powershell
.\.venv\Scripts\python.exe -m pytest scenarios\retailx\tests\checkout\test_checkout_latency.py tests\test_website_architecture.py
```

Cross-scenario UI contracts use Node's built-in modules when available.
Native dialog/mobile layout needs a real-browser check. Offline checks do not
establish live Monitor, SRE or Azure acceptance.

[V25 archive](https://arch-center.azureedge.net/icons/Azure_Public_Service_Icons_V25.zip),
retrieved 16 November 2026. Product names appear next to icons and Microsoft

Microsoft permits copying, distributing and displaying these icons only in
architectural diagrams, training materials or documentation unless explicit
permission is granted, and reserves all other rights. Do not crop, flip,
rotate, distort or change their shape, or use them as the demo product's logo.
Neutral text symbols are used for browser and SRE Agent rather than invented
brand icons. Assets are local; no new runtime package or external icon request
is required.
