Can the Observability Agent feed the SRE Agent?

Two Azure agents, each with its own job. This page compares today's checkout flow with a possible hand-off between them. Illustration only: the hand-off is not built in this demo.

Flow:
Signals and alerts Agent work and actions Possible hand-off (not built) Human hand-off

✅ Where a hand-off helps

  • Many alerts for one problem: the SRE Agent gets one case instead of a flood.
  • A monitoring team works from issues while another team owns the fixes.
  • You want one shared case file before anyone touches production.

⚠️ What it costs

  • The fix starts later: grouping and explaining come first.
  • Two agents investigate the same incident.
  • A small automation in between, which must be built, secured and tested.
  • Relies on a preview feature that has not been dependable here.

🎯 For the checkout demo

  • Each incident has one alert and one cause, so the SRE Agent already starts on the right track.
  • Keep the direct flow. Show the Observability Agent separately, as a chat over the same data.
  • Revisit the hand-off when alert noise is the customer's real problem.
